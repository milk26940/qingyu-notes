# 轻羽笔记软件设计规格

日期：2026-08-24  
状态：已确认，待实施计划

## 1. 产品定义

轻羽是一款 Windows 本地优先的桌面笔记软件。它使用 Markdown 保存正文，以 Notion 的页面、层级、数据库和点击逻辑作为核心操作范式，并将本机现有 Codex 作为全库 Agent 接入。

首版目标：

- 让页面、子页面、数据库和数据库记录遵循统一对象模型。
- 保证笔记可直接读取、可迁移、可备份，不被单一数据库锁定。
- 让用户操作和 Agent 操作进入同一命令、校验、审计和备份流水线。
- 直接复用当前 Windows 用户已经安装并登录的 Codex。
- 保留轻羽自己的 Agent 对话历史，不混入其他 Codex 客户端任务。

首版不包含：

- 多人实时协作。
- 内置云账号与跨设备冲突合并。
- 移动端和 Web 端。
- 完整复刻 Notion 的块编辑器。
- 看板、日历等数据库视图的首批实现；首批只实现表格视图。

## 2. 品牌与界面原则

- 产品名为“轻羽”。
- 应用图标采用用户提供的黑色羽毛线稿。
- 正式图标只保留羽毛主体，使用透明背景；原图中的方框、纸张背景和阴影不进入任务栏图标。
- 界面采用安静、紧凑、工作型布局，不制作营销落地页，不堆叠装饰性卡片。
- 视觉风格服务于高频阅读、编辑、检索和 Agent 操作。

## 3. 技术栈

### 3.1 渲染层

- React 18
- TypeScript
- Vite
- Radix UI
- TailwindCSS
- CodeMirror 6
- Zustand
- `fetch` 与 Tauri IPC

### 3.2 Tauri 原生服务层

- Tauri 2.x
- Rust
- Tokio
- serde、serde-json
- `std::fs` 与 `tokio-fs`
- Tauri commands 与 events
- hyper 仅用于轻羽自身未来的更新、远程资源或同步服务，不代理 Codex 模型连接

### 3.3 本机 Codex

- Tauri 后端启动当前用户 PATH 中的 `codex app-server`。
- 使用默认 `stdio` 传输，以 JSONL 承载 JSON-RPC 消息。
- 不额外实现模型 API 客户端。
- 不复制 Codex 登录文件或提供商凭据。

本机验证基线：

- `codex-cli 0.146.0` 可执行。
- `codex login status` 返回 ChatGPT 登录。
- App Server 初始化握手成功。
- App Server 返回的 `codexHome` 为 `C:\Users\26940\.codex`。

实现不能永久依赖该具体版本号。启动时必须读取 App Server 能力，并使用当前 CLI 生成的协议 schema 或兼容层。

## 4. 总体架构

系统分为五层：

1. React 工作区：页面树、编辑器、数据库视图、搜索和 Agent 面板。
2. Tauri IPC：类型化命令、事件和错误，不暴露任意文件系统调用。
3. Rust 领域服务：页面、数据库、关系、索引、命令事务和备份。
4. Codex App Server：认证、线程、回合、流式事件、审批和 Agent 生命周期。
5. 本地数据：Markdown、结构化 JSON、对话 JSONL、可重建 SQLite 和增量备份。

React 不能直接操作磁盘、Codex 子进程或 SQLite。所有写操作必须经过 Rust 领域服务。

## 5. Notion 式统一页面模型

### 5.1 Page

普通笔记、目录页、数据库页面和数据库记录都属于 Page。Page 至少包含：

- `id`：稳定 UUID。
- `title`：用户可见标题。
- `parent_id`：父页面 UUID，可为空。
- `kind`：普通页面、数据库页面或数据库记录。
- `database_id`：数据库记录所属数据库，可为空。
- `properties`：结构化页面属性。
- `content`：Markdown 正文。

标题、路径和父页面可以改变，UUID 不变。内部链接以 UUID 定位，并保留显示文本。

### 5.2 Database

数据库由一个数据库 Page 和一个 Database Definition 组成。定义包含：

- 字段名称、类型和约束。
- 视图定义。
- 排序、筛选和分组规则。
- 默认打开方式。

数据库记录仍是 Page，既能在表格中编辑属性，也能作为完整页面编辑 Markdown 正文。

首版数据库字段至少支持文本、数字、单选、多选、日期、复选框、页面关系和计算前的只读派生字段。首版只实现表格视图，模型需允许以后增加看板和日历。

### 5.3 Link 与 Relation

- Markdown 支持 `[[页面]]` 交互，并在落盘时保存稳定页面标识。
- 索引器生成正向链接和反向链接。
- 数据库 Relation 也使用 Page UUID。
- 页面重命名和移动不破坏链接。

## 6. 物理文件结构

笔记库使用可读路径体现页面层级：

```text
我的笔记库/
├─ 项目.md
├─ 项目/
│  ├─ 需求分析.md
│  └─ 开发记录.md
├─ 日程数据库.md
├─ 日程数据库/
│  ├─ 会议A.md
│  └─ 会议B.md
├─ attachments/
└─ .noteapp/
   ├─ vault.json
   ├─ databases/
   │  └─ <database-id>.json
   └─ conversations/
      └─ <conversation-id>.jsonl
```

规则：

- Markdown 与 `.noteapp/databases` 中的数据库定义是笔记业务数据的权威来源。
- 每个 Markdown 文件以前置元数据保存 UUID、父页面、类型和属性。
- Windows 禁用字符只影响安全文件名，原始标题保留在元数据中。
- 页面移动同时更新物理路径和 `parent_id`。
- 附件使用稳定标识或冲突安全文件名。
- 搜索索引、缓存、锁和临时文件放在 `%LOCALAPPDATA%\QingYu`，不作为权威数据。

## 7. SQLite 设计边界

轻羽自己的 SQLite 保存：

- 全文搜索索引。
- 页面、链接、反链和属性投影。
- 数据库查询索引。
- Agent 对话索引与 `threadId` 映射。
- 命令、diff、审批和恢复记录。

SQLite 必须可以从 Markdown、数据库 JSON 和对话 JSONL 重建。轻羽不能直接读取或修改 Codex 的 `state_*.sqlite`、`thread_history_*.sqlite` 等内部数据库。

CCSwitch 的 `C:\Users\26940\.cc-switch\cc-switch.db` 也不属于轻羽。CCSwitch 继续负责持久化并回写 Codex 配置，轻羽只监听配置变化并重启 Agent 运行时。

## 8. 主界面与点击逻辑

### 8.1 布局

- 左侧栏：工作区、搜索、收件箱、收藏、页面树、数据库入口和回收站。
- 中间区：当前页面编辑器或数据库视图。
- 右侧栏：可折叠 Agent 对话、执行进度、工具调用、diff 和审批。
- 页面顶部：面包屑、标题、属性、收藏和页面菜单。
- 底部状态区：保存、索引、备份和 Codex 连接状态。

### 8.2 操作语义

- 点击页面节点在中间区打开页面。
- 点击展开箭头只展开或收起子页面。
- 拖拽页面改变层级和顺序。
- 数据库行默认侧边预览，可切换为居中预览或完整页面。
- 点击反向链接先预览来源，再决定是否跳转。
- 右键菜单、顶部菜单、快捷键和 Agent 共享同一命令实现。
- 删除默认进入回收站；永久删除需要二次确认。
- Agent 引用的页面、记录和 diff 可点击定位。
- Agent 上下文可聚焦当前选区、页面、数据库或整个笔记库，但 Agent 可按任务需要搜索全库。

## 9. Codex 集成

### 9.1 复用本机 Codex

轻羽启动本机 `codex app-server`，不覆盖 `CODEX_HOME`，因此直接复用当前用户的：

- `config.toml`。
- `auth.json` 或系统凭据存储。
- 模型提供商和登录状态。
- 会话、技能、插件、MCP 和其他 Codex 状态。

轻羽不得解析、展示、复制、备份或记录 `auth.json`、令牌和提供商密钥。认证过期时调用 Codex 自身登录流程。

轻羽不展示其他 Codex 客户端的历史任务。它只列出自身创建并登记的线程。

### 9.2 App Server 生命周期

- 应用启动后进行 `initialize` / `initialized` 握手。
- 新对话调用 `thread/start`，保存返回的 `threadId`。
- 旧对话调用 `thread/resume`。
- 每个回合通过 `turn/start` 发送请求并消费流式通知。
- 用户停止任务时调用 `turn/interrupt`。
- App Server 崩溃时自动重启并恢复已登记线程。
- CCSwitch 或 `config.toml` 发生有效变化后，提示重启 Agent 运行时；新运行时创建或恢复线程并刷新配置快照。

### 9.3 沙箱与权限

即使全局 Codex 配置更宽松，轻羽创建的线程和回合也必须覆盖：

- `cwd` 为当前笔记库根目录。
- 写入根限制为当前笔记库与轻羽明确的临时目录。
- 默认禁止无关的库外读取。
- 网络访问遵循任务需要和用户设置。
- 删除、覆盖、批量移动、数据库结构变更和恢复操作由轻羽审批层强制确认。

这些限制不能通过修改用户全局 `config.toml` 实现，而应使用 App Server 的线程或回合参数及轻羽工具层。

### 9.4 Agent 语义工具

Agent 写入优先使用轻羽提供的语义工具：

- `page.search`
- `page.read`
- `page.create`
- `page.update`
- `page.move`
- `page.archive`
- `database.query`
- `database.update_schema`
- `database.create_record`
- `database.update_record`
- `relation.link`
- `relation.unlink`
- `relation.backlinks`
- `workspace.diff`
- `workspace.validate`
- `backup.checkpoint`
- `backup.list`
- `backup.restore`

实现首选 App Server 的动态工具请求流，由 Rust 客户端接收工具调用并执行领域命令。动态工具当前属于实验 API，因此实现需：

- 初始化时声明实验能力。
- 针对当前本机 Codex 版本生成并固定协议 schema。
- 启动时进行能力探测。
- 当动态工具不可用时降级为只读 Agent，禁止退化为不受审计的直接写文件。

Codex 可以读取整个笔记库。所有业务写入必须进入轻羽命令总线；不得通过任意 shell 或原始文件写入绕过检查点、校验、索引和审计。

## 10. Agent 对话历史

- 每个笔记库可以创建多个 Agent 对话。
- 对话可以关联整个笔记库、单个页面或数据库。
- Codex 持久线程是继续推理上下文的权威来源。
- 轻羽 SQLite 保存标题、笔记库、页面关系、时间、置顶、归档状态和 `threadId`。
- `.noteapp/conversations` 保存用户可见消息、工具摘要、审批和变更记录的可迁移 JSONL 投影。
- 对话默认归档，不直接永久删除。
- 搜索同时覆盖笔记和轻羽 Agent 对话。
- 如果原 Codex 线程丢失，历史仍可只读查看，并可用历史摘要创建新线程继续。

对话导出不能包含隐藏推理、认证数据或 Codex 内部数据库内容。

## 11. 写入事务

每次用户或 Agent 修改使用相同流水线：

1. 接收语义命令。
2. 解析页面和数据库上下文。
3. 校验 UUID、路径、字段、版本和权限。
4. 对危险或批量操作创建备份检查点并请求确认。
5. 在临时位置生成新内容。
6. 使用原子替换提交文件。
7. 写入命令、diff、工具和对话关联记录。
8. 增量更新 SQLite 投影。
9. 执行提交后校验。
10. 失败时回滚文件并返回结构化错误。

外部编辑器修改 Markdown 时，文件监听器进入同一解析、校验、审计和索引流水线，但不伪造为轻羽用户命令。

## 12. 备份与恢复

备份使用内容寻址的本地增量快照：

- 文件内容按 SHA-256 去重。
- 快照清单记录笔记库状态、时间和触发来源。
- Agent 批量或危险操作前强制建立检查点。
- 连续普通编辑按时间窗口合并，避免每次按键生成快照。
- 默认备份目录为 `%LOCALAPPDATA%\QingYu\backups\<vault-id>`。
- 用户可以改到其他磁盘。
- 支持单页、页面树、数据库和整库恢复。
- 恢复先写入临时目录并校验，成功后再替换。
- ZIP 导出包含 Markdown、附件、数据库定义和轻羽对话历史。
- ZIP 与增量备份都不包含 Codex 认证、配置、令牌或内部数据库。

## 13. 故障处理

- Codex 未安装：编辑功能保持可用，提示定位或安装 Codex。
- 登录过期：调用 Codex 登录流程，不接触令牌内容。
- App Server 崩溃：自动重启并尝试恢复登记线程。
- 配置切换：标记 Agent 运行时需重启，不影响笔记编辑。
- 外部文件变化：重新解析并更新索引。
- 元数据损坏：保留原文件并隔离错误，不静默覆盖。
- SQLite 损坏：从权威文件重建。
- 备份失败：阻止危险 Agent 写入；允许读取和普通手动编辑。
- 写入冲突：保留双方版本并展示 diff。
- Agent 中断：保留已提交步骤的审计记录，清理未提交临时文件。

## 14. 状态边界

Zustand 至少拆分为：

- 工作区与导航状态。
- 当前页面与编辑缓冲区状态。
- 数据库视图状态。
- Agent 连接、线程和流式事件状态。
- 审批、diff 和备份状态。

持久业务数据不能只存在 Zustand。React 状态不得被当作磁盘提交成功的证据，必须等待 Tauri 命令返回提交版本。

## 15. 实施分期

### 阶段 1：技术骨架

- React、Tauri、IPC、三栏外壳和 CodeMirror 6 外壳。
- Rust 文件服务、错误模型和 App Server 生命周期。
- 暂不实现完整业务。

### 阶段 2：页面系统

- Markdown 页面、页面树、UUID、移动、链接、搜索和回收站。

### 阶段 3：数据库

- 字段模型、数据库记录页面、表格视图、筛选、排序和属性编辑。

### 阶段 4：Codex Agent

- 轻羽对话历史、动态工具、流式事件、diff、审批、重启和线程恢复。

### 阶段 5：备份与发布

- 增量快照、恢复、ZIP 导入导出、冲突处理、索引重建、图标和 Windows 安装包。

## 16. 验证策略

验证规模与风险匹配，不追求无意义的全覆盖：

- Rust 单元测试覆盖路径安全、原子写入、关系更新和备份恢复。
- 前端测试覆盖关键状态转换和命令调用。
- 集成测试覆盖页面移动、数据库记录、Agent 工具写入、冲突和恢复。
- App Server 协议测试使用当前 CLI 生成的 schema 和握手探针。
- 发布前用临时笔记库完成真实登录、对话恢复、批量修改、回滚和重启验证。
- 不使用用户正式笔记库执行破坏性测试。

## 17. 验收标准

首个可发布版本至少满足：

- 用户可以创建、编辑、嵌套、移动、搜索和归档 Markdown 页面。
- 用户可以建立数据库并在表格中管理记录页面。
- 页面链接、反链和数据库关系在重命名或移动后保持有效。
- 轻羽可启动本机 Codex，复用现有登录并保留自己的对话历史。
- Agent 可以通过语义工具读取和修改笔记，并显示工具进度与 diff。
- 危险操作无法绕过审批与备份检查点。
- SQLite 删除后可以从权威文件重建。
- 单页和整库备份可以恢复。
- 应用重启后笔记、数据库和 Agent 对话均可继续使用。
